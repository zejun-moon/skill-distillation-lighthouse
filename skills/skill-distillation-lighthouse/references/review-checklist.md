# 评审清单

> 三张清单，对应三个关卡。**每张都是可勾选的**，
> 勾不满就别进下一关。

---

## 关卡 1 · 提交前（作者自查）

### 内容
- [ ] 所有结论标注了 **✅ 实测 / 📄 推断 / 未测**
- [ ] 至少有一个**失败样本**（当时怎么判断错的）
- [ ] 每条结论都有「现象 → 原因 → 处理」三段
- [ ] 判据能让人**自己确认**是不是这个问题（不是只说结论）

### 可用性
- [ ] SKILL.md 有「**什么时候不要用**」章节
- [ ] 每一步都有**可执行的通过条件**（命令 + 明确输出）
- [ ] 排障入口表能覆盖最常见的 5~8 个现象
- [ ] 引用的每个路径**真实存在**

### 脱敏
- [ ] `python3 tools/check_repo.py` 退出码 **0**
- [ ] 按 [`desensitization.md`](desensitization.md) §2 的替换表逐类过了一遍
- [ ] 截图**逐行放大看过**（终端输出、地址栏、标签页）
- [ ] 人工复核过语义性泄露（规模数字、内部弱点、组织信息）
- [ ] 占位符**一眼看出是占位符**（`10.0.0.x` 而不是 `10.0.0.1`） <!-- scan: allow —— 本行是"反例"示范 -->

## 关卡 2 · 合并前（评审者）

### 内容质量
- [ ] 这份技能**解决的是会被重复用的问题**（不是一次性故障）
- [ ] 正文 < 500 行，细节已拆到 `references/`
- [ ] `description` 含**中英触发词枚举** + 同义说法
- [ ] 危险动作写的是「**向用户确认**」，不是自动执行
- [ ] 脚本的参数**没有写死**环境相关的值

### 门禁
- [ ] 扫描规则若被改动 → **测试也改了**，且补了阳性样本
- [ ] 阳性对照跑过：未脱敏素材 → 扫描器**有命中**
- [ ] 自检四类检查全实现，没有跳过的

### 一致性
- [ ] README / CLAUDE.md / AGENTS.md 里提到的**文件和命令都存在**
- [ ] 文档声称的 CI / 插件清单 / 脚本**真的在仓里**
- [ ] 新增或修改的坑在 `pitfalls.md` 里**编号连续**
- [ ] 报告的索引表同步更新了

## 关卡 3 · 发版前（发布者）

- [ ] 版本号**四处一致**（plugin.json / marketplace×2 / CHANGELOG）
- [ ] CHANGELOG 的 `[Unreleased]` 已转成正式版本段落
- [ ] `python3 tools/check_repo.py` 退出码 **0**
- [ ] `python3 -m unittest discover -s tests` 全绿
- [ ] 本地 `git tag vX.Y.Z` 已打
- [ ] 合并后 main 分支的 CI 是绿的
- [ ] **远端回读校验**：文件清单 + 内容 sha256 与本地一致
- [ ] 仓库是 **public**，且**没有意外文件**（密钥、草稿、临时产物）
- [ ] README 的 clone 地址与实际 owner/repo 一致

## 快速自查（一条命令）

```bash
# 结构 + 版本 + 索引 + 脱敏，四类一起跑
python3 tools/check_repo.py && \
python3 -m unittest discover -s tests && \
echo "✅ 可以进下一关"
```

## 一句话原则

> **技能仓的价值 = 别人（包括 AI）能不能照着它做对。**
> 所以评审时问的不是「写得好不好看」，而是
> **「照着这份文档走，能不能做对？做错了能不能自己发现？」**
