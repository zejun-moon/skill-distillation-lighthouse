> 真实命名空间 / uid / 私有仓库地址 / 人名 → 一律替换。

## 2. 遇到的问题（按发生顺序）

### 问题 1：脱敏不是"删一下"，是**改写**

- **第一反应**：以为把 IP 和域名换掉就行
- **实际原因**：真正要脱的不只是格式化的信息，还有**语义层面的**：
  - 规模数字（几个 deployment、几个副本）→ 暴露内部环境特征
  - 内部弱点（"数据库在网络存储上 → 改标题会死锁"）→ 暴露可被利用的缺陷
  - 组织流程（"几个仓因为缺凭据删不掉"）→ 暴露内部权限状态
- **处理**：
  - 形态类 → 逐类替换表（IP / 域名 / ns / uid / 镜像地址 / 账号 / 邮箱 / 路径）
  - 语义类 → **抽象一层**：保留技术结论，去掉可定位的规模与组织细节
    （"12 个 deployment 全单副本" → "该演练环境全部单副本"）
- **沉淀**：这是本仓 `references/desensitization.md` §7 的全部内容

### 问题 2：脚本里写死了环境相关的值 → 既泄露又不可用

- **现象**：直接照抄原生成器，里面的数据源 uid、命名空间、服务清单全是真值
- **实际原因**：本地脚本和本地环境是绑定的
- **处理**：全部改成命令行参数（数据源 uid / 命名空间 / 维度标签 / 服务清单），
  默认值用占位符
- **教训**：**技能仓里的脚本必须"任何人都能跑"**。
  写死的参数 = 泄露 + 不可复用，双输

### 问题 3：扫描器把自己的规则和测试样本也扫了出来

- **现象**：第一次自检报 22 个问题，其中大半在扫描器自己的规则行和测试样本行上
- **实际原因**：规则文件里写着要拦的关键词；测试里必须写真 IP / 真 token 才能验证扫描器
- **处理**：
  - 规则行加行内豁免标记 `# scan: allow`
  - **测试样本改成运行时拼接**（`"192.168." + "2.31"`）
    → 源码里没有完整字面量，扫描器不自指，gitleaks 也不会误判
- **附带收获**：不这么改的话，**gitleaks 会把假 token 当成真密钥，CI 直接红**

### 问题 4：扫描器对真实清单命中 0 处（漏报）

- **现象**：把**未脱敏**的真实采集清单喂扫描器 → **0 命中**
- **实际原因**：规则只覆盖了 IP / 域名 / 凭据，**漏了内部命名空间前缀**
- **处理**：补规则 + 补阳性样本 → 命中数变 2
- **沉淀**：**漏报没人会发现，误报天天打扰你。**
  → 阳性对照（拿未脱敏素材跑）必须成为改规则的固定动作

### 问题 5：推 CI 工作流文件被平台拒绝

- **现象**：推 `.github/workflows/ci.yml` → `403 Resource not accessible by integration`
- **第一反应**：以为是安装范围问题 → 试 git tree API，也是 403
- **实际原因**：GitHub 对 `.github/workflows/*` 的写入**强制要求 token 带 `workflow` scope**，
  连接器的 token 没有。**两条路都堵死，是平台限制不是代码问题**
- **处理**：把文件内容给用户，让其在网页粘贴（web UI 用会话 cookie，不受 scope 限制）
- **连带问题**：仓内文档写着"CI 还有密钥扫描"，文件却不在 → **文档与事实不一致**
  → 沉淀成"发布后必须回读校验"

### 问题 6：逐文件推送把提交历史打散了

- **现象**：一次批量推（git tree API）403 → 改用逐文件推 → 远端变成 30+ 个 commit，
  本地那个干净的提交丢了
- **实际原因**：可用的那条通道**没有批量接口**
- **处理**：接受现状（内容对，历史碎），并在本地保留干净历史 + 备份
- **教训**：**发布通道的能力要在动手前探明**，
  有批量接口就用批量接口；只有逐文件接口时，先想清楚历史碎掉能不能接受

### 问题 7：公共仓的提交带出了真实邮箱

- **现象**：提交作者是 `名字 <真实邮箱>`
- **实际原因**：用用户 token 提交时，作者身份取自 GitHub 账号
- **处理**：告知用户 → 开「Keep my email addresses private」→ 删仓重建 → 重推
- **沉淀**：**发布之前先想一遍"这个仓公开后，谁能看到什么"**。
  提交元数据也是公开内容
